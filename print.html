The Rust++ Doc Book

Introduction

🌐 اقرأ هذا الكتاب بالعربية

Rust++ is a programming language built from Rust 1.101. It keeps everything that makes Rust good — speed like C, no garbage collector, no crashes from bad memory use — and changes the parts that make Rust hard to read and slow to learn.

fn greet(name: &str = "world", times: u32 = 1) {
    for _ in 0..times {
        out!("Hello, {name}!");
    }
}

fn main() {
    greet();
    greet("Rust++", times = 2);
}
Hello, world!
Hello, Rust++!
Hello, Rust++!

  2. Double-click it. It installs Rust++ into %USERPROFILE%\.rustpp and adds it to your PATH.
  3. If the Visual Studio C++ Build Tools are missing, it offers to install them. Say yes: Windows programs are linked with Microsoft’s linker.

Editor

Use DEVR+, the editor made for Rust++: it knows all the new syntax, shows errors as you type and runs your project with F5.

Rust++ also comes with rust++-analyzer, the language server DEVR+ uses. Other editors can use it too: in VS Code, install the rust-analyzer extension and set rust-analyzer.server.path to the rust++-analyzer in ~/.rustpp/bin (%USERPROFILE%\.rustpp\bin on Windows).

Hello, World!

Make a file called main.rs:

fn main() {
    out!("Hello, world!");
}

Compile it and run it:

> rustc main.rs
> ./main          (on Windows: .\main.exe)
Hello, world!

What each part means

  • fn main() — a function called main. Every program starts here.
  • { ... } — the body of the function.
  • out!("...") — prints a line. The ! means out! is a macro: a piece of code that writes code for you.
  • ; — ends the statement.

New in Rust++: out! prints a line. It works exactly like Rust’s println!, which still works too.

Printing values

Put {} where a value should go, or the name of a variable inside {}:

fn main() {
    let name = "Sara";
    let age = 25;

    out!("{name} is {age} years old");
    out!("{} + {} = {}", 2, 3, 2 + 3);
    out!();                        // empty line
    out!("{:?}", [1, 2, 3]);       // {:?} prints lists and other data
    out!("{:.2}", 3.14159);        // 2 digits after the point: 3.14
}
Sara is 25 years old
2 + 3 = 5

[1, 2, 3]
3.14

DEVR+ Plugins

A plugin can change anything in DEVR+: add commands and shortcuts, views, panels, status bar items and pages, change the colors and the whole look, teach the code editor new tricks, and talk to the language server, the terminal and your files.

Use plugins

Open Extensions (Ctrl+Shift+X, the puzzle icon). Each plugin has a switch to turn it on or off, Reload, Edit and Remove.

  • Install from a Folder…: a folder with a plugin.json.
  • Create a Plugin: makes a new plugin from a template and opens it.

A plugin can do anything DEVR+ can, including reading and changing your files and running programs. Install only plugins you trust.

Plugins are kept in the DEVR+ settings folder, in plugins/.

Write a plugin

Create a Plugin makes a folder like this:

my-plugin/
├── plugin.json   what the plugin is
├── main.js       its code
├── style.css     CSS for the whole editor
└── devr.d.ts     the whole API, with explanations (for completion)

plugin.json:

{
  "id": "my-plugin",
  "name": { "en": "My Plugin", "ar": "إضافتي" },
  "version": "0.1.0",
  "description": { "en": "What it does.", "ar": "ماذا تفعل." },
  "main": "main.js",
  "styles": ["style.css"],
  "themes": ["themes/night.json"],
  "devr": "1"
}

Only id is required. A plugin can be only a theme and CSS, with no code.

main.js exports activate, which gets the editor as devr:

// @ts-check
/** @param {import('./devr').Devr} devr */
export function activate(devr) {
  devr.addTranslations({ 'Hello!': 'مرحبًا!' });

  devr.commands.register({
    id: 'my-plugin.hello',
    title: 'My Plugin: Say Hello',
    key: 'Ctrl+Alt+H',
    run: () => devr.ui.toast(devr.t('Hello!'), 'success'),
  });

  const lines = devr.ui.addStatusItem({ icon: 'list-ordered', align: 'right' });
  devr.editor.onChange(() => lines.set(String(devr.editor.model?.getLineCount() ?? '')));
}

Save a file of the plugin and it reloads: change, save, see. Everything the plugin added is removed when it stops or reloads; for things you make with Monaco directly, add them to devr.subscriptions.

Variables

Make a variable with let:

fn main() {
    let x = 5;
    out!("x = {x}");
}

Variables can’t change unless you say so

fn main() {
    let x = 5;
    x = 6; // error: cannot assign twice to immutable variable `x`
}

Add mut (mutable) to let a variable change:

fn main() {
    let mut count = 0;
    count = count + 1;
    count += 1;
    out!("count = {count}"); // 2
}

Why not mut by default? When a value can’t change, you never have to check who changed it. Most variables never change, so the few with mut stand out.

Giving the type yourself

Rust++ works out the type for you, but you can write it after ::

fn main() {
    let age: u32 = 30;
    let price: f64 = 9.99;
    let name: &str = "Ali";
    out!("{name}, {age}, {price}");
}

Remember: : means “has the type”, = means “gets the value”. Rust++ keeps these two meanings everywhere, also in named arguments and default values.

Shadowing

A new let with the same name makes a new variable that hides the old one. It can even have a different type:

fn main() {
    let input = "42";
    let input: i32 = input.parse().unwrap();
    out!("{}", input + 1); // 43
}

Constants

Values that never change in the whole program. The type is required, and the name is in CAPITALS:

const MAX_PLAYERS: u32 = 4;
const GAME: &_static str = "Space";

fn main() {
    out!("{GAME}: up to {MAX_PLAYERS} players");
}

&_static str means “text that lives for the whole program”; see Named Lifetimes.

Types

Every value has a type. The type tells the compiler how much memory the value needs and what you can do with it.

Numbers

TypeHoldsExample
i32whole numbers, −2 147 483 648 to 2 147 483 647 (the default)-7
i64bigger whole numbers9_000_000_000
u8, u32, u64whole numbers, never negative255
usizesizes and positions in listsv.len()

f32smaller, less precise f641.5

i = can be negative, u = unsigned (0 and up), the number = bits.

fn main() {
    let a = 10;           // i32
    let b = 3.0;          // f64
    let big = 1_000_000;  // _ makes big numbers readable

    out!("{}", a / 3);    // 3   (whole-number division)
    out!("{}", a % 3);    // 1   (remainder)
    out!("{}", b / 2.0);  // 1.5
    out!("{}", a as f64 / 4.0); // 2.5  (`as` converts)
    out!("{big}");
}

Numbers of different types don’t mix by accident: a + b above is an error until you convert one of them with as. No silent precision loss.

true and false

fn main() {
    let ready: bool = true;
    let big = 10 > 5; // true
    out!("{} {} {}", ready && big, ready || false, !ready);
}

Characters and text

fn main() {
    let letter: char = 'R';     // one character, single quotes
    let arabic = 'ع';           // any language, any emoji
    let fixed: &str = "hello";  // text written in the program
    let mut owned = String::from("hello"); // text you can grow
    owned.push_str(", world");

    out!("{letter} {arabic} {fixed} {owned}");
    out!("{}", owned.len()); // length in bytes: 12
}

&str vs String is explained in Ownership. For now: "..." is a &str; use String when the text changes.

Tuples and arrays

fn main() {
    let point: (i32, i32) = (3, 4);   // tuple: fixed group, any types
    let (x, y) = point;               // take it apart
    out!("x={x} y={y} first={}", point.0);

    let days = ["Sat", "Sun", "Mon"]; // array: fixed length, one type
    out!("{} of {}", days[0], days.len());

    let zeros = [0; 5];               // [0, 0, 0, 0, 0]
    out!("{zeros:?}");
}

Reading days[10] stops the program with a clear error instead of reading random memory. For lists that grow, use Vec (Collections).

Functions

fn add(a: i32, b: i32) -> i32 {
    a + b
}

fn main() {
    let sum = add(2, 3);
    out!("{sum}");
}
  • fn add — the name.
  • (a: i32, b: i32) — the parameters, each with its type. Types are required here: they are the function’s promise to its callers.
  • -> i32 — the type it gives back. No -> means it gives back nothing.
  • a + b — the last expression, without ;, is the result.

The last line is the result

fn square(n: i32) -> i32 {
    n * n        // no `;` → this is returned
}

fn square_too(n: i32) -> i32 {
    return n * n; // `return` also works; use it to leave early
}

fn main() {
    out!("{} {}", square(4), square_too(5));
}

A ; turns an expression into a statement that gives nothing. Writing n * n; in square is an error: the function promised an i32 and gives nothing.

Blocks are expressions too

fn main() {
    let grade = 85;
    let label = if grade >= 90 { "excellent" } else { "good" };

    let area = {
        let w = 3;
        let h = 4;
        w * h
    };
    out!("{label} {area}");
}

Two Rust++ extras

Functions in Rust++ can be called with names, and parameters can have default values:

fn rect(width: u32, height: u32 = 1) -> u32 {
    width * height
}

fn main() {
    out!("{}", rect(width = 3, height = 4)); // 12
    out!("{}", rect(5));                     // 5, height = 1
}

The next two chapters explain them.

Named Arguments

New in Rust++: when calling a function, write name = value to say which parameter gets which value.

fn transfer(from: &str, to: &str, amount: u32) {
    out!("{amount} from {from} to {to}");
}

fn main() {
    transfer("Ali", "Sara", 100);                      // which is which?
    transfer(from = "Ali", to = "Sara", amount = 100); // clear
    transfer(amount = 100, to = "Sara", from = "Ali"); // any order
}

All three calls do the same thing. Named calls are clearer to read, and you can’t swap from and to by mistake.

Positional first, then named

You can give the first values by position and name the rest:

fn area(width: u32, height: u32) -> u32 {
    width * height
}

fn main() {
    out!("{}", area(3, height = 4));
}

After the first named value, all the rest must be named:

fn area(width: u32, height: u32) -> u32 {
    width * height
}

fn main() {
    area(width = 3, 4); // error: positional argument after a named argument
}

Methods and constructors

Named arguments work on methods and on Type::new too:

struct Window {
    width: u32,
    height: u32,
}

impl Window {
    fn new(width: u32, height: u32) -> Window {
        Window { width, height }
    }

    fn resize(&mut self, width: u32, height: u32) {
        self.width = width;
        self.height = height;
    }
}

fn main() {
    let mut w = Window::new(width = 800, height = 600);
    w.resize(height = 1080, width = 1920);
    out!("{}x{}", w.width, w.height);
}

Mistakes the compiler catches

You writeError
area(widht = 3, height = 4)this function has no parameter named widht
area(3, width = 4)parameter width is given more than once
area(width = 3)missing argument for parameter height

Why = and not :

In Rust++, : always means “has the type” (let x: u32) and = always means “gets the value” (let x = 5). A named argument gives a value, so it uses =.

Cost

None. The compiler puts the values back in the right order before building the program; the result is the same as a positional call.

Default Values

New in Rust++: a parameter can have a default value: name: Type = value. Leave it out when calling, and the default is used.

fn connect(host: &str, port: u16 = 443, secure: bool = true) {
    out!("{host}:{port} secure={secure}");
}

fn main() {
    connect("example.com");                       // port 443, secure
    connect("example.com", 8080);                 // secure
    connect("localhost", port = 3000, secure = false);
    connect("localhost", secure = false);         // port 443
}
example.com:443 secure=true
example.com:8080 secure=true
localhost:3000 secure=false
localhost:443 secure=false

With named arguments you can skip any parameter that has a default, not only the last ones: connect("localhost", secure = false) keeps the default port.

In types

Defaults work in impl blocks too, which removes the need for many new_with_... functions:

struct Counter {
    value: i64,
    step: i64,
}

impl Counter {
    fn new(start: i64 = 0, step: i64 = 1) -> Counter {
        Counter { value: start, step }
    }

    fn tick(&mut self, times: i64 = 1) {
        self.value += self.step * times;
    }
}

fn main() {
    let mut a = Counter::new();
    a.tick();
    a.tick(times = 5);
    out!("{}", a.value); // 6

    let b = Counter::new(step = 10);
    out!("{}", b.value + b.step); // 10
}

Rules

  • The default must be a constant: numbers, "text", true, 'c', None, constants, and math on them (MAX / 2).

    fn hello(name: String = String::from("world")) {} // error: not a constant

fn main() {}

    For a String default, take &str instead: fn hello(name: &str = "world").

  • Allowed on functions and in impl Type { ... }. Not yet in traits.

  • Parameters without a default must still be given.

Cost

None. Each default is stored once as a hidden constant, and a call that leaves a parameter out uses that constant as if you had written it.

Control Flow

if

fn main() {
    let temp = 38;

    if temp > 40 {
        out!("very hot");
    } else if temp > 30 {
        out!("hot");
    } else {
        out!("nice");
    }

    // `if` gives a value
    let wear = if temp > 30 { "t-shirt" } else { "jacket" };
    out!("{wear}");
}

The condition must be a bool. if count { ... } with a number is an error: write if count != 0.

loop, while, for

fn main() {
    // loop: forever, until `break`. `break value` gives a value.
    let mut n = 1;
    let first_big = loop {
        n *= 2;
        if n > 100 { break n; }
    };
    out!("{first_big}"); // 128

    // while: as long as the condition is true
    let mut left = 3;
    while left > 0 {
        out!("{left}...");
        left -= 1;
    }

    // for: over a range or a list
    for i in 0..3 {          // 0, 1, 2
        out!("i = {i}");
    }
    for i in 1..=3 {         // 1, 2, 3
        out!("i = {i}");
    }
    for name in ["Ali", "Sara"] {
        out!("hi {name}");
    }
}

Use for whenever you can: it can’t go past the end of a list. continue skips to the next round.

match

match compares a value against patterns, top to bottom, and runs the first one that fits:

fn main() {
    let code = 404;
    let text = match code {
        200 => "OK",
        301 | 302 => "moved",          // either one
        400..=499 => "your mistake",   // a range
        _ => "something else",         // anything left
    };
    out!("{text}");
}

A match must cover every possible value; _ catches the rest. If you forget a case, the program doesn’t compile. This becomes very useful with enums.

Ownership

Ownership is how Rust++ manages memory without a garbage collector and without you calling free. It is the one idea that makes Rust++ both fast and safe, so take your time with this chapter.

Three rules

  1. Every value has one owner: the variable that holds it.
  2. When the owner goes away (its { } block ends), the value is freed.
  3. Giving the value to someone else moves it: the old variable can’t use it any more.
fn main() {
    {
        let s = String::from("hello"); // s owns the text
        out!("{s}");
    }                                  // block ends: the text is freed
}

No leaks (the value is always freed) and no double frees (only one owner frees it). The compiler checks this; it costs nothing at run time.

Moving

fn main() {
    let a = String::from("hello");
    let b = a;           // the text moves from `a` to `b`
    out!("{a}");         // error: borrow of moved value: `a`
}

Why? If both a and b owned the text, both would free it. So a gives the text away and becomes unusable.

The same happens when you pass a value to a function:

fn shout(text: String) {
    out!("{}!", text.to_uppercase());
}   // `text` is freed here

fn main() {
    let msg = String::from("hi");
    shout(msg);           // `msg` moves into the function
    // out!("{msg}");     // error: `msg` was moved
}

Copy: small values are copied, not moved

Numbers, bool, char, and tuples/arrays of them are small, so they are copied instead:

fn main() {
    let x = 5;
    let y = x;           // copy
    out!("{x} {y}");     // both fine
}

clone: copy on purpose

To really have two copies of a String or a Vec, ask for it with .clone(). It’s visible in the code, so you always see where memory is copied:

fn main() {
    let a = String::from("hello");
    let b = a.clone();
    out!("{a} {b}");
}

String vs &str

  • String owns its text. It can grow and change.
  • &str borrows text that someone else owns (a String, or text written in the program).

Most functions only need to read text, so they take &str. That’s borrowing, the next chapter.

Borrowing

Moving a value into every function that reads it would be annoying. Instead you lend it: &value makes a reference, a pointer that borrows the value without owning it.

fn length(text: &String) -> usize {
    text.len()
}   // `text` is only borrowed: nothing is freed

fn main() {
    let s = String::from("hello");
    let n = length(&s);   // lend `s`
    out!("{s} has {n} bytes"); // `s` is still ours
}

Changing through a borrow: &mut

& lends for reading. &mut lends for changing:

fn add_world(text: &mut String) {
    text.push_str(", world");
}

fn main() {
    let mut s = String::from("hello");
    add_world(&mut s);
    out!("{s}"); // hello, world
}

The borrowing rule

At any moment you can have either

  • any number of & (readers), or
  • exactly one &mut (one writer),

but not both.

fn main() {
    let mut list = vec![1, 2, 3];
    let first = &list[0];   // reader
    list.push(4);           // writer while the reader still exists: error
    out!("{first}");
}

This is not fussiness: push may move the list to a bigger place in memory, and first would then point at freed memory. In C++ this compiles and crashes later; in Rust++ it doesn’t compile.

A borrow ends after its last use, so this is fine:

fn main() {
    let mut list = vec![1, 2, 3];
    let first = list[0];    // a copy of the number, not a borrow
    list.push(4);
    out!("{first} {list:?}");
}

A reference can’t outlive its value

fn main() {
    let r;
    {
        let s = String::from("short life");
        r = &s;
    }               // `s` is freed here...
    out!("{r}");    // ...so `r` would point at nothing: error
}

When a function returns a reference, the compiler needs to know which value it borrows from, to check this rule at the call. In Rust that’s what lifetimes ('a) are for. Rust++ has an easier way: the next chapter.

Borrow Sources

New in Rust++: when a function returns a reference, write which parameters it borrows from: &{x, y} T.

fn longest(x: &str, y: &str) -> &{x, y} str {
    if x.len() >= y.len() { x } else { y }
}

fn main() {
    let a = String::from("apple");
    let b = String::from("fig");
    out!("{}", longest(&a, &b)); // apple
}

Read -> &{x, y} str as: returns a &str that is borrowed from x or y. Now the compiler knows the result is only valid while both a and b are alive.

Only the parameters that matter

fn pick(list: &Vec<i32>, index: &usize) -> &{list} i32 {
    &list[*index]
}

fn main() {
    let numbers = vec![10, 20, 30];
    let x = {
        let i = 1;
        pick(&numbers, &i)   // `i` is freed after this block...
    };
    out!("{x}");             // ...and that's fine: x borrows only `numbers`
}

Because the result is &{list} i32, the compiler knows it doesn’t borrow from index. Precise information means fewer false errors.

Anywhere in the return type

fn first_word(text: &mut String) -> (&{text} str, usize) {
    let end = text.find(' ').unwrap_or(text.len());
    (&text[..end], end)
}

fn get<T>(items: &[T], i: usize) -> Option<&{items} T> {
    items.get(i)
}

fn main() {
    let mut s = String::from("hello world");
    let (w, n) = first_word(&mut s);
    out!("{w} {n}");
    out!("{:?}", get(&[1, 2, 3], 2)); // Some(3)
}

self

In methods, self is a source like any other:

struct Library {
    books: Vec<String>,
}

impl Library {
    fn first(&self) -> &{self} str {
        &self.books[0]
    }

    fn first_or(&self, other: &str, use_other: bool) -> &{self, other} str {
        if use_other { other } else { &self.books[0] }
    }
}

fn main() {
    let lib = Library { books: vec![String::from("Dune")] };
    out!("{} {}", lib.first(), lib.first_or("none", true));
}

Do I always need it?

No. Like in Rust, when a function takes one reference, or takes &self, the compiler already knows where the result comes from:

fn trim_dots(text: &str) -> &str {    // only one source: no {..} needed
    text.trim_matches('.')
}

fn main() {
    out!("{}", trim_dots("..hi.."));
}

Write &{...} when there are two or more references to choose from.

Rules

  • Each name must be a parameter that is a reference (&T or &mut T), or self.
  • There’s no runtime cost: the compiler turns &{x, y} into lifetimes and checks exactly the same rules.

Named Lifetimes

Borrow sources cover functions. One place still needs a name for “how long a borrow lives”: a struct that holds a reference.

New in Rust++: lifetime names are written like normal names that start with _: _a, _text. 'static is _static.

struct Parser<_a> {
    input: &_a str,
    pos: usize,
}

impl<_a> Parser<_a> {
    fn new(input: &_a str) -> Parser<_a> {
        Parser { input, pos: 0 }
    }

    fn next_word(&mut self) -> Option<&_a str> {
        let rest = &self.input[self.pos..];
        let rest = rest.trim_start();
        if rest.is_empty() {
            return None;
        }
        let start = self.input.len() - rest.len();
        let end = rest.find(' ').unwrap_or(rest.len());
        self.pos = start + end;
        Some(&rest[..end])
    }
}

fn main() {
    let text = String::from("borrow without fear");
    let mut p = Parser::new(&text);
    while let Some(word) = p.next_word() {
        out!("{word}");
    }
}

Read Parser<_a> as: a Parser that borrows something for a time called _a, and input: &_a str as: input is borrowed for that time. A Parser can’t outlive the text it reads; the compiler checks it.

_static

_static means “for the whole program”. Text written in the program is &_static str:

const GREETING: &_static str = "salam";

fn pick_color(dark: bool) -> &_static str {
    if dark { "black" } else { "white" }
}

fn main() {
    out!("{GREETING} {}", pick_color(true));
}

It also works as a bound, meaning “holds no short-lived borrows”:

fn keep<T: _static + std::fmt::Debug>(value: T) -> Box<dyn std::fmt::Debug + _static> {
    Box::new(value)
}

fn main() {
    out!("{:?}", keep(42));
}

Rules

  • A lifetime name is _ followed by a small letter: _a, _x, _input.
  • It goes in <...> and after &.
  • A variable called _a is still just a variable.
  • Rust’s 'a still works for now. It will be removed; see Coming Soon.

Structs

A struct groups values that belong together under one name.

struct User {
    name: String,
    age: u32,
    active: bool,
}

fn main() {
    let mut user = User {
        name: String::from("Sara"),
        age: 25,
        active: true,
    };

    user.age += 1;
    out!("{} is {} (active: {})", user.name, user.age, user.active);
}

  • Make one with Name { field: value, ... }.
  • Read a field with .field. To change fields, the variable needs mut.

Shortcuts

struct Point {
    x: i32,
    y: i32,
}

fn make(x: i32, y: i32) -> Point {
    Point { x, y }                   // same as Point { x: x, y: y }
}

fn main() {
    let a = make(1, 2);
    let b = Point { y: 10, ..a };    // the rest of the fields from `a`
    let Point { x, y } = b;          // take it apart
    out!("{x} {y}");
}

Tuple structs and unit structs

struct Meters(f64);          // one unnamed field: a number with a meaning
struct Color(u8, u8, u8);
struct Marker;               // no fields

fn main() {
    let d = Meters(5.5);
    let red = Color(255, 0, 0);
    let _m = Marker;
    out!("{} {}", d.0, red.0);

Meters(5.5) and a plain 5.5 are different types, so you can’t pass seconds where meters are expected.

Printing a struct

Add #[derive(Debug)] and print it with {:?} (or {:#?} for one field per line):

#[derive(Debug)]
struct Point {
    x: i32,
    y: i32,
}

fn main() {
    let p = Point { x: 3, y: 4 };
    out!("{p:?}");   // Point { x: 3, y: 4 }
}

derive writes common code for you. Other useful ones: Clone, Copy, PartialEq (for ==), Default.

Methods

Functions that belong to a type go in an impl block:

struct Rect {
    width: f64,
    height: f64,
}

impl Rect {
    // no `self`: called as Rect::new(...)
    fn new(width: f64, height: f64 = 1.0) -> Rect {
        Rect { width, height }
    }

    fn square(size: f64) -> Rect {
        Rect::new(width = size, height = size)
    }

    // &self: reads the value
    fn area(&self) -> f64 {
        self.width * self.height
    }

    // &mut self: changes the value
    fn scale(&mut self, by: f64 = 2.0) {
        self.width *= by;
        self.height *= by;
    }

    // self: takes the value (it is moved into the method)
    fn into_square(self) -> Rect {
        Rect::square(self.width.max(self.height))
    }
}

fn main() {
    let mut r = Rect::new(width = 3.0, height = 4.0);
    out!("{}", r.area());        // 12
    r.scale();
    out!("{}", r.area());        // 48
    r.scale(by = 0.5);
    let s = r.into_square();
    out!("{}", s.area());        // 16
    // r can't be used any more: into_square took it
}

Pick the weakest one that works: &self if you only read.

Self (capital S) is a short name for the type of the impl: fn new(...) -> Self means -> Rect.

Rust++: named arguments and default values work on methods: Rect::new(width = 3.0), r.scale(by = 0.5).

Enums and match

A struct is “this and that”. An enum is “this or that”: a value that is one of several kinds.

enum Direction {
    Up,
    Down,
    Left,
    Right,
}

fn turn(d: Direction) -> &_static str {
    match d {
        Direction::Up => "going up",
        Direction::Down => "going down",
        Direction::Left | Direction::Right => "going sideways",
    }
}

fn main() {
    out!("{}", turn(Direction::Left));
}

Kinds can carry data

Each kind can hold its own values:

enum Shape {
    Circle { radius: f64 },
    Rect { width: f64, height: f64 },
    Point,
}

impl Shape {
    fn area(&self) -> f64 {
        match self {
            Shape::Circle { radius } => 3.14159 * radius * radius,
            Shape::Rect { width, height } => width * height,
            Shape::Point => 0.0,
        }
    }
}

fn main() {
    let shapes = [
        Shape::Circle { radius: 1.0 },
        Shape::Rect { width: 2.0, height: 3.0 },
        Shape::Point,
    ];
    for s in &shapes {
        out!("{:.2}", s.area());
    }
}

match must handle every kind. Add a new kind to Shape and the compiler shows you every match that needs updating: no case is forgotten.

Option: a value or nothing

Rust++ has no null. A value that may be missing is an Option:

fn find_age(name: &str) -> Option<u32> {
    if name == "Sara" { Some(25) } else { None }
}

fn main() {
    match find_age("Sara") {
        Some(age) => out!("age {age}"),
        None => out!("unknown"),
    }

    // shorter forms
    if let Some(age) = find_age("Ali") {
        out!("Ali is {age}");
    }
    let age = find_age("Ali").unwrap_or(0);
    out!("{age}");
}

You can’t use an Option<u32> as a u32 by accident: you must handle None first. That removes a whole family of crashes.

Patterns in match

fn describe(point: (i32, i32)) -> String {
    match point {
        (0, 0) => String::from("center"),
        (x, 0) => format!("on the x line at {x}"),
        (0, y) => format!("on the y line at {y}"),
        (x, y) if x == y => String::from("on the diagonal"),
        _ => String::from("somewhere"),
    }
}

fn main() {
    out!("{}", describe((3, 3)));
}

Traits and Generics

Traits: what a type can do

A trait is a list of methods. A type that has those methods implements the trait.

trait Speak {
    fn name(&self) -> String;

    // a method with a body is a default: types can keep or replace it
    fn greet(&self) -> String {
        format!("Hello from {}", self.name())
    }
}

struct Cat;
struct Robot {
    id: u32,
}

impl Speak for Cat {
    fn name(&self) -> String {
        String::from("a cat")
    }
}

impl Speak for Robot {
    fn name(&self) -> String {
        format!("robot #{}", self.id)
    }
    fn greet(&self) -> String {
        format!("BEEP. I AM {}", self.name().to_uppercase())
    }
}

fn main() {
    out!("{}", Cat.greet());
    out!("{}", Robot { id: 7 }.greet());
}

Generics: one function, many types

<T> is a type parameter: a placeholder for “some type”. T: Speak says “any type that implements Speak”:

trait Speak {
    fn name(&self) -> String;
}

struct Cat;
impl Speak for Cat {
    fn name(&self) -> String { String::from("cat") }
}

fn introduce<T: Speak>(thing: &T) {
    out!("This is {}", thing.name());
}

fn largest<T: PartialOrd + Copy>(items: &[T]) -> T {
    let mut best = items[0];
    for &item in items {
        if item > best {
            best = item;
        }
    }
    best
}

fn main() {
    introduce(&Cat);
    out!("{}", largest(&[3, 9, 2]));
    out!("{}", largest(&[1.5, 0.5]));
    out!("{}", largest(&['a', 'z', 'm']));
}

The compiler makes a separate, fully optimized copy of a generic function for each type you use. Generics cost nothing at run time.

Collections

Vec: a list that grows

fn main() {
    let mut scores: Vec<u32> = Vec::new();
    scores.push(90);
    scores.push(75);
    scores.push(60);

    let names = vec!["Ali", "Sara", "Omar"]; // vec! makes one with values

    out!("{} scores, first {}", scores.len(), scores[0]);
    out!("{:?}", scores.get(10));            // None: no crash

    for s in &scores {                       // & = read, don't take
        out!("score {s}");
    }
    for s in &mut scores {                   // &mut = change each one
        *s += 5;
    }
    out!("{scores:?} {names:?}");

    let last = scores.pop();                 // Some(65)
    out!("{last:?}");
}

v[i] stops the program if i is past the end; v.get(i) gives an Option instead.

Working with lists: iterators

Instead of writing loops by hand, chain small steps:

fn main() {
    let prices = vec![12, 5, 40, 8, 25];

    let total: u32 = prices.iter().sum();
    let cheap: Vec<u32> = prices.iter().filter(|&&p| p < 20).cloned().collect();
    let doubled: Vec<u32> = prices.iter().map(|p| p * 2).collect();
    let max = prices.iter().max();

    out!("{total} {cheap:?} {doubled:?} {max:?}");

    for (i, p) in prices.iter().enumerate() {
        if i < 2 { out!("#{i}: {p}"); }
    }
}

|p| p * 2 is a closure: a small function without a name. Iterator chains compile to the same machine code as a hand-written loop.

String

fn main() {
    let mut s = String::from("Rust");
    s.push_str("++");
    s.push('!');

    let joined = format!("{s} is {}", "fast");
    out!("{joined}");

    for word in "one two three".split(' ') {
        out!("{word}");
    }

HashMap: look up a value by a key

use std::collections::HashMap;

fn main() {
    let mut stock: HashMap<&str, u32> = HashMap::new();
    stock.insert("apple", 3);
    stock.insert("fig", 10);

    *stock.entry("apple").or_insert(0) += 2;  // add, or start at 0
    *stock.entry("kiwi").or_insert(0) += 1;

    if let Some(n) = stock.get("fig") {
        out!("figs: {n}");
    }
    let mut items: Vec<_> = stock.iter().collect();
    items.sort();
    out!("{items:?}");
}

A HashMap has no order. Sort the items, or use BTreeMap, when order matters.

Errors

Rust++ has two kinds of errors:

  • Bugs, which should never happen: the program stops with panic!.
  • Expected failures, like a missing file or bad input: the function returns a Result and the caller decides what to do.

Result

fn divide(a: f64, b: f64) -> Result<f64, String> {
    if b == 0.0 {
        Err(String::from("can't divide by zero"))
    } else {
        Ok(a / b)
    }
}

fn main() {
    match divide(10.0, 4.0) {
        Ok(v) => out!("result {v}"),
        Err(e) => out!("error: {e}"),
    }
    match divide(1.0, 0.0) {
        Ok(v) => out!("result {v}"),
        Err(e) => out!("error: {e}"),
    }
}

Result<T, E> is either Ok(value) or Err(error). Like Option, you can’t use the value without handling the error first.

? : pass the error up

Inside a function that returns Result, ? after a call means: if this is an error, return it now; otherwise give me the value.

fn parse_pair(text: &str) -> Result<(i32, i32), std::num::ParseIntError> {
    let mut parts = text.split(',');
    let a = parts.next().unwrap_or("").trim().parse::<i32>()?;
    let b = parts.next().unwrap_or("").trim().parse::<i32>()?;
    Ok((a, b))
}

fn main() {
    out!("{:?}", parse_pair("3, 4"));   // Ok((3, 4))
    out!("{:?}", parse_pair("3, x"));   // Err(ParseIntError { kind: InvalidDigit })
}

Quick and simple

CallWhen it’s an error
.unwrap()stop the program
.expect("message")stop the program with your message
.unwrap_or(value)use value instead
.unwrap_or_default()use 0, "", false, …
?return the error to the caller

Use unwrap in small programs and tests. In real code, prefer ? or a match.

main can return a Result

use std::fs;

fn main() -> Result<(), std::io::Error> {
    fs::write("hello.txt", "salam")?;
    let text = fs::read_to_string("hello.txt")?;
    out!("{text}");
    fs::remove_file("hello.txt")?;
    Ok(())
}

If an error reaches main, the program prints it and exits with an error code.

Modules

As a program grows, split it into modules. A module is a named group of functions, types and other modules.

mod shapes {
    pub struct Circle {
        pub radius: f64,
    }

    impl Circle {
        pub fn area(&self) -> f64 {
            PI * self.radius * self.radius
        }
    }

    const PI: f64 = 3.14159; // private: only usable inside `shapes`
}

use shapes::Circle;

fn main() {
    let c = Circle { radius: 2.0 };
    out!("{:.2}", c.area());
}
  • Everything is private by default. pub makes it usable outside the module.
  • use brings a name into scope so you don’t have to write the full path.
  • :: separates path parts: shapes::Circle, std::collections::HashMap.

One module per file

In a Cargo project, mod shapes; (with ;) loads the module from a file:

src/
├── main.rs        mod shapes;  use shapes::Circle;
└── shapes.rs      pub struct Circle { ... }

A folder works too: src/shapes/mod.rs, or src/shapes.rs next to a src/shapes/ folder for its sub-modules.

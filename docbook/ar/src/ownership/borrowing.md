# الاستعارة

نقل القيمة إلى كل دالة تقرؤها سيكون مزعجًا. بدلًا من ذلك **تُعيرها**:
`&value` تصنع *مرجعًا*، مؤشرًا يستعير القيمة بدون أن يملكها.

```rust
fn length(text: &String) -> usize {
    text.len()
}   // `text` مستعار فقط: لا يُحرَّر شيء

fn main() {
    let s = String::from("hello");
    let n = length(&s);   // نعير `s`
    out!("{s} has {n} bytes"); // `s` ما زال لنا
}
```

## التعديل عبر الاستعارة: &mut

`&` تعير للقراءة. و`&mut` تعير للتعديل:

```rust
fn add_world(text: &mut String) {
    text.push_str(", world");
}

fn main() {
    let mut s = String::from("hello");
    add_world(&mut s);
    out!("{s}"); // hello, world
}
```

## قاعدة الاستعارة

في أي لحظة يمكن أن يكون عندك **إما**

- أي عدد من `&` (قرّاء)، **أو**
- `&mut` واحدة فقط (كاتب واحد)،

لكن ليس الاثنين معًا.

```rust,compile_fail
fn main() {
    let mut list = vec![1, 2, 3];
    let first = &list[0];   // قارئ
    list.push(4);           // كاتب والقارئ ما زال موجودًا: خطأ
    out!("{first}");
}
```

هذا ليس تشددًا: `push` قد تنقل القائمة إلى مكان أكبر في الذاكرة، فيصبح
`first` مشيرًا إلى ذاكرة محررة. في C++ يُترجم هذا ثم ينهار لاحقًا؛ وفي Rodet
لا يُترجم.

الاستعارة تنتهي بعد آخر استخدام لها، لذلك هذا صحيح:

```rust
fn main() {
    let mut list = vec![1, 2, 3];
    let first = list[0];    // نسخة من الرقم، وليست استعارة
    list.push(4);
    out!("{first} {list:?}");
}
```

## المرجع لا يعيش أطول من قيمته

```rust,compile_fail
fn main() {
    let r;
    {
        let s = String::from("short life");
        r = &s;
    }               // يُحرَّر `s` هنا...
    out!("{r}");    // ...فسيشير `r` إلى لا شيء: خطأ
}
```

عندما **ترجع الدالة مرجعًا**، يحتاج المترجم أن يعرف من أي قيمة يستعير،
ليتحقق من هذه القاعدة عند الاستدعاء. في Rust هذا ما تفعله الأعمار (`'a`).
في Rodet طريقة أسهل: الفصل التالي.
